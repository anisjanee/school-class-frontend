# School Journal Pro

Полноценный локальный школьный журнал: frontend + FastAPI + SQLite. Интерфейс рассчитан на учителей, учеников и родителей.

## Что реализовано

### Аккаунты и права
- регистрация ученика и родителя;
- создание аккаунтов учителя/ученика/родителя учителем;
- вход и выход через API;
- сессия Bearer Token на 24 часа;
- отключение аккаунта;
- привязка родителя/ученика к профилю ученика;
- серверная проверка роли для защищённых операций.

### Управление школой
- ученики: создание, редактирование, удаление;
- пользователи: роли, статус доступа, привязка к ученику;
- предметы и преподаватели;
- оценки 1–10 и комментарии;
- уведомления.

### Учебный процесс
- недельное расписание;
- номер урока, время, кабинет, класс и преподаватель;
- домашние задания со сроком сдачи;
- личный просмотр расписания и заданий для ученика/родителя.

### Общение
- личные сообщения;
- отметка сообщений прочитанными;
- разные права доступа для ролей.

### Интерфейс
- полностью обновлённый адаптивный дизайн;
- боковая навигация;
- dashboard со статистикой;
- карточки, таблицы, статусы и уведомления;
- мобильная версия;
- единая визуальная система для всех кабинетов.

## Стек

- HTML5
- CSS3
- Vanilla JavaScript
- Python 3.10+
- FastAPI
- Uvicorn
- SQLite
- PBKDF2-HMAC-SHA256 для хранения паролей

## Локальный запуск

### Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Windows PowerShell вместо `source`:

```powershell
.venv\Scripts\Activate.ps1
```

После запуска API:

```text
http://127.0.0.1:8000
http://127.0.0.1:8000/docs
```

### Frontend

В отдельном терминале из корня проекта:

```bash
python3 -m http.server 5500
```

Открой:

```text
http://127.0.0.1:5500/portal.html
```

В GitHub Codespaces используй вкладку **PORTS** и открой порты `8000` и `5500`.

## Важно

Основной новый кабинет находится в `portal.html`. Старый статический интерфейс проекта в `index.html` сохранён отдельно.

База `backend/school.db` создаётся/обновляется автоматически при первом запуске новой версии backend. Перед экспериментами с данными можно сделать копию этого файла.
